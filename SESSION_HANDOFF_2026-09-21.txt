PRIVA SESSION HANDOFF
Date: 2026-09-21

Purpose
-------
Document the backend and frontend work completed in this session for the equity curve, account balance display, and autonomous exit behavior.

Root-cause finding
------------------
The autonomous agent returned immediately whenever the current strategy signal was hold. Because of that early return, it never fetched the existing position and never evaluated take-profit or stop-loss rules during a hold cycle. This could leave positions open indefinitely when the market signal was neutral.

Backend changes
---------------
- Updated backend/app/agent_loop.py.
  - Hold cycles now check existing futures or spot positions for take-profit and stop-loss exits.
  - Autonomous market mode checks both futures and spot positions.
  - Per-cycle balance snapshots are retained in memory, capped at 1,000 records.
  - Supabase balance snapshot logging is attempted when the execution client provides account equity.
  - Snapshot failures are logged without failing the trading cycle.
- Updated backend/app/main.py.
  - GET /account/balance now also returns:
    - balance
    - futures_equity
    - spot_usdt
  - Added GET /account/balance-history.
  - The history endpoint reads Supabase snapshots first, then in-process agent snapshots, then endpoint-poll snapshots.
- Updated backend/app/supabase_logging.py.
  - Added log_balance_snapshot().
  - Added fetch_balance_snapshots().
- Updated backend/supabase_multi_user.sql.
  - Added the balance_snapshots table.
  - Added session/time index.

Known limitation
----------------
The equity curve is initially empty or has only one point until the first account poll or agent cycle records a snapshot. Persistent history requires SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY to be configured on the backend.

Static-position root-cause fix
------------------------------
- The agent could detect an open position from Supabase cycle logs but lacked entry price and side when Bitget's live position read returned an execution error. It then treated the position as existing and repeatedly logged `skipped_existing_position` without evaluating exits.
- Added a futures cycle-log fallback for degraded exchange position reads. Explicit successful empty position responses are still trusted, so stale logs do not recreate positions when Bitget confirms they are gone.
- Successful futures and spot close records now persist `closed_position_side`, `qty`, and `entry_price` in `order_result`. This lets cycle-derived `/positions` and P&L reconstruction remove the closed lot.
- Added a regression test covering an exchange position-read failure followed by a real take-profit close attempt.
- Full backend suite after this fix: 101 passed, 2 existing FastAPI deprecation warnings.
